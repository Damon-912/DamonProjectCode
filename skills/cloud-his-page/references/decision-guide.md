## 界面类型识别标准

### 类型1: 单表操作（CRUD）

**识别特征：**
- ✅ 存在查询条件区域（输入框、下拉框等）
- ✅ 只存在一个数据列表（表格形式）

**必须使用：** 包装组件模式（SingleTableOperation）

**判断示例：**

| 原型图描述 | 判断结果 |
|-----------|---------|
| 用户管理：查询用户、列表展示、新增用户弹窗 | ✅ 单表CRUD |
| 字典维护：查询字典、列表展示、新增/编辑/删除 | ✅ 单表CRUD |
| 日志查询：只有查询和列表，无新增功能 | ❌ 不是（属于简单列表） |

---

### 类型2: 主从表结构

**识别特征：**
- ✅ 上半部分主表信息（通常为表单）
- ✅ 下半部分明细列表（通常为表格）
- ✅ 主从关联关系（主表ID关联明细）

**必须使用：** ParentChildTableOperation

**典型场景：**
- 订单管理（订单头 + 订单明细）
- 入库单（入库主表 + 入库明细）
- 出库单（出库主表 + 出库明细）

---

### 类型3: 审核流程

**识别特征：**
- ✅ 有审核状态列
- ✅ 有审核/反审核按钮
- ✅ 有批量操作功能

**必须使用：** OrderReviewComponent

**典型场景：**
- 采购申请审核
- 费用报销审核
- 药品调拨审核

---

### 类型4: 查询导出

**识别特征：**
- ✅ 左侧查询条件
- ✅ 右侧数据列表
- ✅ 有导出按钮
- ❌ 无新增/编辑/删除功能

**推荐方案：** 自定义组件（参考 SimpleListTemplate）

---

### 类型5: 复杂表单

**识别特征：**
- ✅ 多步骤表单（步骤条）
- ✅ 复杂布局（嵌套、分组）
- ✅ 特殊验证逻辑（跨字段验证、条件验证）

**推荐方案：** 自定义组件（需说明理由）

---

### 类型6: 特殊UI界面

**识别特征：**
- ✅ 树形结构（左侧树形菜单 + 右侧详情）
- ✅ 自定义布局（非标准布局）
- ✅ 特殊交互方式（拖拽、画布等）

**推荐方案：** 自定义组件（需说明理由）

## 开发模式对比

| 开发模式 | 代码量 | 复杂度 | 灵活性 | 适用场景 |
|---------|--------|--------|--------|----------|
| 包装组件模式 | 150-250行 | 低 | 中 | 标准CRUD |
| 动态组件配置 | 50-100行 | 低 | 低 | 纯配置界面 |
| 自定义组件 | 300-500行 | 高 | 高 | 复杂交互 |

## 决策检查清单

在选择开发模式前，确认以下问题：

### 必答问题

- [ ] 界面是否有查询条件区域？
- [ ] 界面是否有数据列表？
- [ ] 界面是否有新增/编辑功能？
- [ ] 界面是否有主从表结构？
- [ ] 界面是否有审核流程？

### 判断逻辑

```
IF 有查询条件 AND 有数据列表 AND 有新增/编辑功能 AND 无主从表 AND 无审核流程 THEN
    使用包装组件模式（SingleTableOperation）
    
ELSE IF 有主从表结构 THEN
    使用 ParentChildTableOperation
    
ELSE IF 有审核流程 THEN
    使用 OrderReviewComponent
    
ELSE IF 只有查询和列表 THEN
    使用自定义组件（SimpleListTemplate）
    
ELSE
    使用自定义组件（需说明理由）
END IF
```

## 常见误判案例

### 案例1: 误判为自定义组件

**场景：** 用户管理界面，包含查询、列表、新增、编辑、删除功能。

**错误判断：** 使用自定义组件开发

**正确判断：** 必须使用包装组件模式

**原因：** 符合标准CRUD特征，使用包装组件可减少70%代码量

---

### 案例2: 误判为单表CRUD

**场景：** 入库单管理，上方表单填写入库信息，下方表格填写入库明细。

**错误判断：** 使用 SingleTableOperation

**正确判断：** 必须使用 ParentChildTableOperation

**原因：** 存在主从表结构，主表与明细表有关联关系

---

### 案例3: 忽略审核流程

**场景：** 采购申请管理，有查询、列表、新增、编辑、删除，还有审核功能。

**错误判断：** 使用 SingleTableOperation

**正确判断：** 必须使用 OrderReviewComponent

**原因：** 存在审核流程，需要专门的审核组件处理审核逻辑

---

### 案例4: 被关联交互复杂度误导

**场景：** 不良事件上报界面
- 列表：查询条件 + 状态Tab + 数据表格 + 分页
- 新建：打开事件类型选择弹窗 → 打开复杂上报表单Drawer
- 详情：三栏布局Drawer（事件详情 + 审核操作 + 时间轴）

**错误判断：** 使用自定义组件开发整个页面，因为关联交互太复杂

**正确判断：** 列表使用包装组件，复杂交互用子组件实现

**原因：** 
- 列表本身完全符合标准单列表操作界面特征
- Drawer的复杂程度不影响列表的模式选择
- 正确架构：SingleTableOperation + EventTypeModal + EventFormDrawer + EventDetailDrawer

**代码结构示例：**
```jsx
class EventReport extends Component {
    render() {
        return (
            <div className="event-report">
                {/* 列表页面：使用包装组件 */}
                <SingleTableOperation
                    skip01040073={true}
                    categoryData={this.categoryData}
                    hardcodedColumns={this.getColumns()}
                    hardcodedQueryFormData={this.getQueryFormData()}
                />
                {/* 关联交互：独立子组件 */}
                <EventTypeModal />
                <EventFormDrawer />
                <EventDetailDrawer />
            </div>
        );
    }
}
```

## 特殊情况处理

### 情况1: 标准CRUD但有额外功能

如果界面符合标准CRUD特征，但有一些额外功能（如导出、特殊按钮），可以：

1. 优先使用包装组件模式
2. 通过 `categoryData` 配置额外功能
3. 必要时包装组件中添加自定义逻辑

```jsx
class XxxManagement extends Component {
    // 自定义导出逻辑
    handleCustomExport = () => {
        // 自定义导出实现
    };
    
    render() {
        return (
            <div className="xxx-management">
                <SingleTableOperation
                    // ... 标准配置
                    exportBtnFlag="Y"
                    onExport={this.handleCustomExport}
                />
            </div>
        );
    }
}
```

---

### 情况2: 多个动态组件组合

如果界面包含多个独立的功能区域，可以：

1. 拆分为多个子组件
2. 每个子组件使用合适的动态组件
3. 主组件组合子组件

```jsx
class ComplexManagement extends Component {
    render() {
        return (
            <div className="complex-management">
                <Row gutter={16}>
                    <Col span={12}>
                        <SubComponentA />  {/* 使用包装组件 */}
                    </Col>
                    <Col span={12}>
                        <SubComponentB />  {/* 使用包装组件 */}
                    </Col>
                </Row>
            </div>
        );
    }
}
```
