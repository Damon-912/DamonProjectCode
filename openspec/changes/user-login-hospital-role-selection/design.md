## Context

DRG/DIP医保控费预警系统现有登录流程为单步登录：用户输入用户名密码后直接跳转主页。后端 `src.Logon.Interface` 已提供完整的登录相关接口：
- `01010001` IsValidUser：验证用户名密码，返回用户基本信息
- `01010002` Logon：完成登录，需要传入 userID、groupID、hospID 等参数
- `01010004` GetLogonGroupByUserId：根据用户ID查询该用户可选的登录权限列表（医院+角色组合）

当前前端登录页面 `pages/Login/index.tsx` 使用模拟登录，未对接真实后端接口。

医疗信息系统特点：
- 一个用户可能属于多个医院（如集团医院、医联体场景）
- 一个用户可能拥有多个角色（如医生+管理员）
- 不同医院的数据需要隔离，不同角色的权限不同
- 登录时必须明确选择本次登录的医院和角色

## Goals / Non-Goals

**Goals:**
- 实现两步登录流程：验证身份 → 选择医院角色 → 完成登录
- 医院角色选择页面展示用户关联的所有医院+角色组合
- 支持按医院名称、角色名称搜索筛选
- 登录成功后保存完整的session信息（含hospID、groupID）到localStorage
- 保持与现有UI风格一致

**Non-Goals:**
- 不实现多因素认证（短信验证码等）
- 不实现密码找回功能
- 不实现记住密码功能（仅记住用户名）
- 不修改后端接口逻辑

## Decisions

### 1. 登录流程设计：两步登录

**选择**：
1. 第一步（Login）：输入用户名密码，调用01010001验证
2. 第二步（SelectHospRole）：展示医院角色列表，用户选择
3. 调用01010002完成登录，跳转主页

**理由**：
- 符合医疗信息系统标准登录流程
- 必须先验证身份才能获取权限列表（安全考虑）
- 与后端接口设计匹配

### 2. 医院角色展示方式：卡片式列表

**选择**：以卡片形式展示每个医院+角色组合，卡片内显示医院名称、角色名称、医院编码等信息

**理由**：
- 比下拉框更直观，用户可一眼看到所有选项
- 支持按医院/角色搜索筛选
- 每个卡片可显示更多信息（如医院级别、角色权限等）

### 3. 状态管理：localStorage + React Context

**选择**：
- localStorage存储session信息（持久化）
- React Context提供全局登录状态
- 登录选择页面通过URL参数或state传递用户信息

**理由**：
- 保持与现有request.ts中的session读取逻辑兼容
- 支持页面刷新后保持登录状态

## Risks / Trade-offs

- **[风险] 用户可能只有一个医院+角色组合** → 此时应自动选择并跳过第二步，直接进入主页
- **[风险] 后端01010004接口返回的权限列表可能为空** → 前端需处理此情况，提示用户联系管理员分配权限
- **[权衡] 两步登录增加用户操作步骤** → 但医疗系统安全性要求更高，这是必要的
- **[风险] 登录过程中断（如刷新页面）** → 需要处理中间状态，避免用户卡在中间步骤
