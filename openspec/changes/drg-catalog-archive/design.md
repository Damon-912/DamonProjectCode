## Context

DRGs目录信息表功能已完成开发，是DRG医保控费预警系统基础数据管理模块的一个子功能。该功能用于管理各地方DRGs目录信息，支持按省、市、DRG代码、DRG描述进行查询，以及新增、编辑和删除操作。

当前架构为前后端分离模式：
- 前端：React 18 + Ant Design 5，通过统一API网关调用后端服务
- 后端：IRIS ObjectScript，接口通过 `src.DRG.BasicData.InterFace` 入口类路由到 `src.DRG.BasicData.DRGCataLog` 业务类
- 数据：`User.HBDRGCataLog` 持久化类映射为SQL表 `HB_DRGCataLog`

## Goals / Non-Goals

**Goals:**
- 完整归档DRGs目录信息表的数据库表结构、接口设计、前端页面和菜单配置
- 记录各组件间的数据流转关系和依赖关系
- 为后续功能维护和扩展提供参考依据

**Non-Goals:**
- 不涉及功能修改或新增
- 不涉及性能优化或重构

## Decisions

### 1. 表结构设计

**决策**: HB_DRGCataLog 表使用省(ProvinceDr)、市(CityDr)外键关联行政区划表，并存储行政区划代码(Admvs)冗余字段。

**理由**: 行政区划代码(Admvs)是国家医保接口规范要求的必传参数，存储冗余字段避免每次查询时需要联表获取。省市外键关联CB_Province和CB_City表保证数据一致性。

**备选方案**: 不存储Admvs冗余字段，每次通过City_Dr联表获取 → 被否决，因为医保接口调用频繁，减少联表开销更优。

### 2. 唯一性约束

**决策**: 通过联合索引 `DataIndex(Code, ProvinceDr, CityDr)` 和业务层校验确保同一省市下DRG代码不重复。

**理由**: 不同省市可以存在相同的DRG代码（地方版本差异），因此唯一性范围是省市+代码组合。

### 3. 前端省市联动

**决策**: 查询条件和编辑弹窗均采用省市二级联动下拉，省变化时异步加载市数据。

**理由**: 与系统其他基础数据维护页面保持一致的交互模式，复用已有的 `getProvinceData`(01010007) 和 `getCityData`(01010008) 接口。

### 4. 接口编号分配

**决策**: 分配接口编号 02010041(查询)、02010042(保存)、02010043(删除)。

**理由**: 遵循系统接口编号规范：02-基础数据模块、01-数据管理、00-默认子模块、041/042/043-顺序号。

## Risks / Trade-offs

- **[Admvs冗余字段一致性]** → 编辑时通过省市联动自动获取Admvs值，避免手动输入导致不一致
- **[无逻辑删除]** → 当前采用物理删除，若后续需要审计追溯需要改造为逻辑删除
- **[前端省市数据加载]** → 编辑弹窗打开时需异步加载市数据，存在短暂等待，已通过loading状态缓解
