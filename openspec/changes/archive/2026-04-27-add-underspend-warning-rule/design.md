## Context

当前DRG预警系统的规则类型有5种：01=费用超支、02=低倍率、03=高倍率、04=编码异常、05=分解住院。其中"费用超支"(01)基于 `totalFee > drgPayStandard * thresholdValue / 100` 判断，"低倍率"(02)基于 `totalFee < drgPayStandard * (100 - thresholdValue) / 100` 判断。

用户需求：增加"费用过低"预警规则类型，当医疗费用明显低于DRG支付标准时触发预警。这区别于"低倍率"——低倍率关注的是倍率区间，费用过低关注的是绝对费用偏差（费用盈余场景）。

后端 `CheckWarningTrigger` 方法是核心触发判断逻辑，`QueryWarningStats` 方法负责类型统计映射，`GenerateWarningMessage` 方法负责预警消息生成。当前 `GenerateWarningMessage` 仅根据费用差异正负显示"超出/低于"，未根据规则类型生成差异化语义消息（如"费用超支"、"低倍率"、"高倍率"等）。需要增加 `ruleType` 参数，使预警消息包含规则类型的业务语义描述。

## Goals / Non-Goals

**Goals:**
- 新增规则类型 `06=费用过低`，完整支持前后端
- 后端 `CheckWarningTrigger` 增加 `ruleType="06"` 的触发逻辑
- 后端 `GenerateWarningMessage` 增加 `ruleType` 参数，根据规则类型生成差异化预警消息
- 前端所有涉及规则类型的地方（搜索、编辑、预览、统计）都支持新类型
- 预警预览弹窗根据规则类型正确显示"超过"或"低于"

**Non-Goals:**
- 不修改现有5种规则类型的触发逻辑
- 不修改数据库表结构（RuleType 为字符串，新增枚举值无需DDL变更）
- 不新增后端接口
- 不涉及DIP模式下的预警逻辑

## Decisions

### 1. 新增规则类型编码选择 `06`

**选择**: 在现有 01-05 之后顺延使用 `06`

**替代方案**: 使用字母编码如 `A` — 不采用，因为与现有数字编码体系不一致

**理由**: RuleType 字段为 `%String` 类型，`06` 与现有编码格式一致，排序友好，前端映射只需在常量中增加一行

### 2. "费用过低"触发逻辑设计

**选择**: `totalFee < drgPayStandard * (100 - thresholdValue) / 100`，即费用低于标准的 (100-阈值)% 时触发

**示例**: 阈值30%时，当费用低于标准的70%时触发预警

**替代方案**: 直接用 `totalFee < drgPayStandard * thresholdValue / 100`（费用低于标准的阈值%） — 语义不直观

**理由**: 与"费用超支"(01)的逻辑对称——01是 `totalFee > drgPayStandard * thresholdValue / 100`（超过标准N%触发），06则是低于标准(100-N)%触发，用户填写的阈值含义为"偏差幅度"

### 3. 前端预览示例描述逻辑优化

**选择**: 使用规则类型集合判断方向：超支类型(01,03,05)显示"超过"，偏低类型(02,06)显示"低于"

**替代方案**: 当前只判断 `ruleType === '02'` — 不够全面，新增06后同样需要显示"低于"

**理由**: 统一用集合判断更清晰可维护

### 4. GenerateWarningMessage 根据 ruleType 生成差异化消息

**选择**: 为 `GenerateWarningMessage` 方法增加 `ruleType` 参数，根据不同规则类型生成不同语义前缀的预警消息

**当前消息格式**: `规则名称：患者费用总额xxx元，DRG支付标准xxx元，超出/低于xxx元（+xx%）`

**改进消息格式**:
- 01(费用超支): `费用超支预警：患者费用总额xxx元，超出DRG支付标准xxx元（+xx%）`
- 02(低倍率): `低倍率预警：患者费用总额xxx元，低于DRG支付标准xxx元（-xx%）`
- 03(高倍率): `高倍率预警：患者费用总额xxx元，超出DRG支付标准xxx元（+xx%）`
- 04(编码异常): `编码异常预警：患者费用总额xxx元`
- 05(分解住院): `分解住院预警：患者费用总额xxx元`
- 06(费用过低): `费用过低预警：患者费用总额xxx元，低于DRG支付标准xxx元（-xx%）`

**替代方案**: 保持现有格式不变，仅在规则名称中体现差异 — 不采用，因为规则名称是用户自定义的，不同规则可能有相同类型但不同名称

**理由**: ruleType 是标准化的分类编码，适合作为预警消息的语义前缀，使消息更具业务含义和可读性。同时 `AddWarningRecord` 方法中已持有 `ruleTypeVal` 变量，调用时只需多传一个参数

## Risks / Trade-offs

- [向后兼容性] 已有数据中不会有 ruleType=06 的记录 → 无迁移风险
- [逻辑与02的区分] "费用过低"与"低倍率"触发公式相同 → 需要在规则描述和预警消息中体现差异，两者业务含义不同：低倍率关注倍率区间分类，费用过低关注费用盈余风险
- [前端类型] `WarningStats.typeStats` 需要增加 `'06'` 属性 → TypeScript 类型扩展，不影响运行时
