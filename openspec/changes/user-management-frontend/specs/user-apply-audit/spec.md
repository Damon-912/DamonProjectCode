## ADDED Requirements

### Requirement: 用户申请列表查询
系统SHALL提供用户申请记录分页列表页面，对接后端接口 code 01030107，支持按审核状态、医院、申请日期范围筛选。

#### Scenario: 默认加载待审核列表
- **WHEN** 用户进入用户申请审核页面
- **THEN** 系统默认加载审核状态为"待审核(R)"的申请记录列表，显示申请编码、姓名、性别、所属医院、手机号、证件号、申请时间、审核状态、审核人、审核时间列

#### Scenario: 按条件筛选申请记录
- **WHEN** 用户选择审核状态(待审核/已通过/已驳回/全部)、选择医院、设置申请日期范围后点击查询
- **THEN** 系统调用 FindApplyLog 接口，传递筛选参数，刷新列表

#### Scenario: 审核状态标签展示
- **WHEN** 列表中申请记录的审核状态不同
- **THEN** 系统用不同颜色标签展示：待审核(R)=橙色、已通过(Y)=绿色、已驳回(N)=红色

### Requirement: 用户申请详情查看
系统SHALL支持查看用户申请的详细信息，对接后端接口 code 01030108。

#### Scenario: 查看申请详情
- **WHEN** 用户点击申请列表某行的"详情"按钮
- **THEN** 系统调用 UserAuditLogDetail 接口获取详情，在弹窗中展示完整申请信息，包含：基本信息（编码、姓名、性别、手机号、证件信息）、医院信息、审核信息（审核状态、审核人、审核组、审核备注）、申请时间

### Requirement: 审核用户申请
系统SHALL提供审核用户申请功能，对接后端接口 code 01030106，支持通过或驳回操作；后端使用session.userID作为审核人。

#### Scenario: 打开审核弹窗
- **WHEN** 用户点击待审核记录的"审核"按钮
- **THEN** 系统打开审核弹窗，展示申请详情，并提供"通过"和"驳回"操作按钮，以及审核备注输入框

#### Scenario: 审核通过
- **WHEN** 用户点击"通过"按钮
- **THEN** 系统调用 Aduit 接口（auditStatus="Y"，携带session信息），后端自动创建用户并分配权限角色，成功后刷新列表并显示成功提示

#### Scenario: 审核驳回
- **WHEN** 用户点击"驳回"按钮
- **THEN** 系统调用 Aduit 接口（auditStatus="N"，携带session信息），成功后刷新列表并显示成功提示

#### Scenario: 审核失败处理
- **WHEN** 审核接口返回错误
- **THEN** 系统显示错误信息提示，不关闭审核弹窗，允许用户重试

#### Scenario: 无权限审核
- **WHEN** 当前用户session的groupID无审核权限时尝试审核
- **THEN** 后端返回权限不足错误，前端提示"您没有权限执行审核操作"

### Requirement: 用户注册申请提交
系统SHALL支持在用户申请审核页面提交新的用户注册申请，对接后端接口 code 01030105。

#### Scenario: 打开申请弹窗
- **WHEN** 用户点击"新增申请"按钮
- **THEN** 系统打开申请表单弹窗，包含用户编码、姓名(必填)、性别(必填)、手机号(必填)、证件类型、证件号、所属医院(必填)、简介、审核组(必填)字段

#### Scenario: 提交注册申请
- **WHEN** 用户填写完表单点击提交
- **THEN** 系统调用 UserApply 接口，成功后关闭弹窗并刷新列表，申请状态默认为"待审核(R)"

### Requirement: 用户申请审核菜单入口
系统SHALL在"系统管理"菜单下新增"用户申请审核"菜单项，key为 `system-user-apply`。

#### Scenario: 菜单项可见
- **WHEN** 用户展开系统管理菜单
- **THEN** 菜单中显示"用户申请审核"项，位于"用户管理"之后
