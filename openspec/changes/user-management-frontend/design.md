## Context

DRG/DIP医保控费预警系统后端已完整实现用户管理模块，包含4个核心业务类：
- `src.User.Interface`：统一接口层，暴露11个API端点（code: 01030101~01030111）
- `src.User.User`：用户CRUD核心逻辑，操作 `HB_User`、`HB_UserLinkHosp`、`HB_UserExt` 表
- `src.User.UserAuditLog`：用户申请与审核逻辑，操作 `HB_UserAuditLog` 表
- `src.User.UserLogonLoc`：用户权限角色管理，操作 `HB_UserLogonLoc` 表

当前前端状态：
- `Users.tsx` 和 `Roles.tsx` 均为占位页面，仅显示"功能开发中"
- `api/system.ts` 仅包含接口服务配置相关API（01010016~01010018）
- 系统管理菜单下有6个菜单项（用户管理、角色权限、菜单配置、医疗机构管理、接口服务配置、接口日志）
- 缺少"用户申请审核"菜单

技术约束：
- 前端使用 React 18 + Ant Design 5 + TypeScript
- API调用统一使用 `api/request.ts` 中的 `invoke(code, params, session, pagination)` 函数
- 后端接口返回格式为 `{ errorCode, errorMessage, result: { total, rows } }`
- **Session校验**：所有后端接口都需要 `session` 参数进行身份校验，包含 `userID`, `locID`, `groupID`, `hospID`, `sessionID` 等字段；`invoke` 函数默认从 `localStorage` 读取 session 自动传入

## Goals / Non-Goals

**Goals:**
- 完整实现用户管理前端功能，对接全部11个后端接口
- 实现用户列表分页查询、新增/编辑用户、用户申请审核、权限角色分配
- 保持与现有前端页面（如Hospitals.tsx、Interfaces.tsx）一致的UI风格和交互模式
- 新增"用户申请审核"菜单项

**Non-Goals:**
- 不修改后端接口逻辑
- 不实现用户登录/注册流程（已有Login页面）
- 不实现密码修改/重置功能（后端接口未提供独立密码修改API）
- 不实现角色管理页面（Roles.tsx的完整实现属于独立需求）

## Decisions

### 1. 页面结构决策：三页面方案

**选择**：采用三个独立页面分别承载用户管理、用户申请审核、用户权限角色管理

**理由**：
- 用户管理与用户申请审核是不同业务场景（日常管理 vs 审批流程），分离更清晰
- 用户权限角色作为用户管理子功能，嵌入用户管理页面的详情弹窗中（而非独立页面）
- 与现有菜单结构一致（系统管理下按功能域划分）

**备选方案**：将申请审核作为用户管理页面的Tab → 不选，因为审核流程独立于日常用户管理，操作角色可能不同

### 2. API层设计：统一在 system.ts 中扩展

**选择**：在现有 `api/system.ts` 中新增用户管理相关接口定义

**理由**：
- 用户管理属于系统管理模块，与现有接口服务配置API同属一个业务域
- 保持API文件组织的一致性
- 复用已有的 `invoke` 函数和类型定义

### 3. 用户详情交互：弹窗模式

**选择**：用户权限角色管理通过点击用户行的"详情"按钮打开Modal弹窗，弹窗内展示用户基本信息和权限角色列表

**理由**：
- 与项目中其他页面的详情查看交互一致
- 避免页面跳转，操作更流畅
- 权限角色列表与用户信息关联紧密，弹窗展示更直观

### 4. 用户申请审核交互：列表+审核弹窗

**选择**：申请审核页面以列表为主，点击"审核"按钮打开审核弹窗，显示申请详情并支持通过/驳回

**理由**：
- 审核操作频繁，列表模式便于批量处理
- 审核弹窗展示完整申请信息，便于审核人做出判断
- 与后端Aduit接口的参数结构匹配

## Risks / Trade-offs

- **[风险] 后端UpdateUserConf接口(code:01030103)缺少Debug示例** → 实现时参照AddUserConf参数结构，编辑时传递userDr字段区分新增/修改
- **[风险] 审核通过时后端自动创建用户并分配权限角色，是事务性操作** → 前端需处理审核失败场景，提示用户检查申请信息
- **[权衡] 用户管理页面同时包含用户CRUD和权限角色管理，功能较重** → 通过弹窗分层（新增/编辑弹窗 + 权限角色弹窗）降低复杂度
- **[风险] 用户扩展字段(wxOPENID, hrUSERID, approveID)在后端动态处理** → 前端暂不展示这些扩展字段，后续根据需求扩展
- **[风险] Session过期或无效时后端返回错误** → 前端需统一处理session失效场景，跳转登录页或提示重新登录；`FindUserDetail` 接口会根据session中的 `groupID` 和 `hospID` 自动过滤数据权限
