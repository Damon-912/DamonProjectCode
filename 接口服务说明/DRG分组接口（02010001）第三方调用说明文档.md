# DRG分组接口服务说明文档

**接口服务编码**：02010001  
**文档版本**：V1.0  
**更新日期**：2026-04-01

---

## 一、接口概述

### 1.1 接口功能
DRG分组器接口（服务编码：02010001）是DRG医保控费预警系统的核心接口，用于将患者的诊断、手术等诊疗信息进行DRG分组，返回分组结果、权重、风险等级等关键信息。

### 1.2 接口地址
```
POST /api/invoke/02010001
```

### 1.3 数据格式
- 请求Content-Type：`application/json`
- 字符编码：UTF-8

### 1.4 注意事项
- ICD编码版本均为国家医保局发布的医保版
- 主诊断必填且只能有一个
- 手术或操作信息选填
- 医疗机构算法信息需要在"DRG核心算法配置维护"菜单中提前维护

## 二、请求参数说明

### 2.1 请求体结构

```json
{
  "mainDiagnosisCode": "string",     // 主诊断ICD-10编码（必填）
  "mainOperationCode": "string",     // 主手术ICD-9-CM-3编码（选填）
  "diseInfo": [...],                 // 诊断信息数组（选填）
  "oprnInfo": [...],                 // 手术/操作信息数组（选填）
  "hospInfo": [...],                 // 医疗机构信息数组（选填）
  "sex": "string",                   // 性别：1=男, 2=女
  "age": number,                     // 年龄（岁）
  "ageGroupDays": number,            // 新生儿出生天数（0-28）
  "newbornFlag": "string",           // 新生儿标志：1=是, 0=否
  "respiratorTime": number,          // 呼吸机使用时长（小时）
  "ecmoFlag": "string",              // ECMO标志：1=是, 0=否
  "transplantFlag": "string",        // 器官移植标志：1=是, 0=否
  "marrowTransplantFlag": "string",  // 骨髓移植标志：1=是, 0=否
  "hivFlag": "string",               // HIV感染标志：1=是, 0=否
  "traumaLevel": number,             // 创伤等级（0-5）
  "department": "string",            // 科室编码或名称
  "dischargeType": "string",         // 离院方式
  "hospitalDays": number,            // 住院天数
  "totalCost": number,               // 总费用
  "weight": number,                 // 体重（新生儿，单位：克）
  "medicalRecordId": "string",       // 病案ID（用于业务关联）
  "admissionNo": "string"            // 住院号（用于业务关联）
}
```

### 2.2 参数详细说明

#### 2.2.1 基础信息（必填）

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| mainDiagnosisCode | string | **是** | 主诊断ICD-10编码，如"I21.0" |

#### 2.2.2 诊断信息（diseInfo）

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| mainFlag | number | **是** | 主诊断标志：1=主诊断, 0=其他诊断 |
| diagSn | number | **是** | 诊断序号，从1开始 |
| diagCode | string | **是** | 诊断代码（ICD-10） |
| diagName | string | 否 | 诊断名称 |

**示例**：
```json
"diseInfo": [
  { "mainFlag": 1, "diagSn": 1, "diagCode": "I21.0", "diagName": "急性透壁性前壁心肌梗死" },
  { "mainFlag": 0, "diagSn": 2, "diagCode": "E11.9", "diagName": "2型糖尿病" }
]
```

#### 2.2.3 手术/操作信息（oprnInfo）

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| mainFlag | string | **是** | 主手术标志：1=主手术, 0=其他手术 |
| oprnSn | number | **是** | 手术序号，从1开始 |
| oprnCode | string | **是** | 手术代码（ICD-9-CM-3） |
| oprnName | string | 否 | 手术名称 |

**示例**：
```json
"oprnInfo": [
  { "mainFlag": "1", "oprnSn": 1, "oprnCode": "36.0600", "oprnName": "药物洗脱冠状动脉支架置入" }
]
```

#### 2.2.4 医疗机构信息（hospInfo）

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| hisHospCode | string | **是** | HIS机构代码 |
| code | string | 否 | 医疗机构代码 |
| name | string | 否 | 医疗机构名称 |

**示例**：
```json
"hospInfo": [
  { "hisHospCode": "HOSPITAL001", "code": "110101", "name": "某市人民医院" }
]
```

#### 2.2.5 患者基本信息

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| sex | string | 否 | 性别：1=男, 2=女，默认"1" |
| age | number | 否 | 年龄（岁），默认0 |
| ageGroupDays | number | 否 | 新生儿出生天数（0-28） |
| newbornFlag | string | 否 | 新生儿标志：1=是, 0=否 |

#### 2.2.6 特殊情况标志

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| respiratorTime | number | 否 | 有创呼吸机使用时长（小时），≥96小时进入MDCA先期分组 |
| ecmoFlag | string | 否 | ECMO标志：1=是, 0=否，有ECMO进入MDCA先期分组 |
| transplantFlag | string | 否 | 器官移植标志：1=是, 0=否，有移植进入MDCA先期分组 |
| marrowTransplantFlag | string | 否 | 骨髓移植标志：1=是, 0=否，有移植进入MDCA先期分组 |
| hivFlag | string | 否 | HIV感染标志：1=是, 0=否，有HIV进入MDCY先期分组 |
| traumaLevel | number | 否 | 多发创伤等级（0-5），≥2级进入MDCZ先期分组 |

#### 2.2.7 其他信息

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| department | string | 否 | 科室编码或名称 |
| dischargeType | string | 否 | 离院方式 |
| hospitalDays | number | 否 | 住院天数 |
| totalCost | number | 否 | 总费用 |
| weight | number | 否 | 体重（新生儿，单位：克） |
| medicalRecordId | string | 否 | 病案ID，仅用于业务关联 |
| admissionNo | string | 否 | 住院号，仅用于业务关联 |

## 三、响应参数说明

### 3.1 成功响应

```json
{
  "errorCode": "0",
  "errorMessage": "",
  "code": "string",           // DRG代码
  "desc": "string",           // DRG描述
  "mdc": "string",            // MDC代码
  "mdcDesc": "string",        // MDC描述
  "drg": "string",            // DRG代码（同code）
  "drgDesc": "string",        // DRG描述（同desc）
  "weight": number,           // DRG权重
  "benchmarkCost": number,    // 标杆费用
  "riskLevel": "string",      // 风险等级：低/中/高
  "ccFlag": boolean,          // 是否有合并症
  "mccFlag": boolean,         // 是否有严重合并症
  "checkTime": "string",      // 分组时间
  "complicationInfo": [...],   // 合并症信息数组
  "drgInfo": [...],           // DRG信息数组
  "hospAlgorithmInfo": [...]  // 医疗机构算法信息数组
}
```

### 3.2 响应参数详细说明

#### 3.2.1 基础响应字段

| 参数名 | 类型 | 说明 |
|--------|------|------|
| errorCode | string | 错误码，"0"表示成功 |
| errorMessage | string | 错误信息，成功时为空 |

#### 3.2.2 分组结果字段

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | string | DRG分组代码，如"ES31" |
| desc | string | DRG分组描述，如"糖尿病，有严重并发症" |
| mdc | string | MDC主诊大类代码，如"MDCC" |
| mdcDesc | string | MDC主诊大类描述，如"眼疾病及功能障碍" |
| drg | string | DRG代码（与code相同） |
| drgDesc | string | DRG描述（与desc相同） |
| weight | number | 该DRG的权重系数 |
| benchmarkCost | number | 该DRG的标杆费用 |
| riskLevel | string | 风险等级：低/中/高 |
| ccFlag | boolean | 是否有合并症（CC） |
| mccFlag | boolean | 是否有严重合并症（MCC） |
| checkTime | string | 分组操作时间 |

#### 3.2.3 合并症信息（complicationInfo）

| 参数名 | 类型 | 说明 |
|--------|------|------|
| diagCode | string | 合并症诊断代码 |
| diagName | string | 合并症诊断名称 |
| complication | string | 合并症等级：MCC/CC |
| complicationDesc | string | 合并症描述 |

#### 3.2.4 DRG信息（drgInfo）

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | string | DRG代码 |
| desc | string | DRG描述 |

#### 3.2.5 医疗机构算法信息（hospAlgorithmInfo）

| 参数名 | 类型 | 说明 |
|--------|------|------|
| hisHospCode | string | HIS机构代码 |
| hospCode | string | 医疗机构代码 |
| hospName | string | 医疗机构名称 |
| drg | string | 关联的DRG代码 |
| drgDesc | string | 关联的DRG描述 |
| points | string/number | 点数 |
| pipValue | string/number | PIP值 |
| dgdov | string/number | DGDOV值 |
| payStandard | string/number | 支付标准 |

### 3.3 错误响应

  "code": "",

  "weight": 0,
  "benchmarkCost": 0,

## 六、常见问题

### 6.1 为什么返回的DRG代码为空？
请检查主诊断编码是否正确，必须是医保版ICD-10编码。

### 6.2 如何获取完整的分组结果？
确保传递完整的诊断和手术信息，特别是主诊断必须准确。

### 6.3 为什么没有返回医疗机构算法信息？
需要在系统中提前配置医疗机构的DRG核心算法信息，包括点数、费率等参数。

### 6.4 先期分组是如何判断的？
系统会根据以下条件自动判断先期分组：
- 器官移植 → MDCA
- 骨髓移植 → MDCA
- ECMO治疗 → MDCA
- 呼吸机≥96小时 → MDCA
- 新生儿 → MDCP
- HIV感染 → MDCY
- 多发严重创伤（等级≥2） → MDCZ
